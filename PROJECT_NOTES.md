# Диплом: классификация изображений растений

Дата заметок: 2026-05-02.

## Цель проекта

Построить исследовательский и демонстрационный проект для классификации изображений растений:

- обучить модель на датасете с изображениями растений;
- реализовать PyQt-приложение для загрузки одного изображения, нескольких изображений или папки;
- показывать результат классификации в виде общей сетки и отдельной карточки/просмотра по каждому изображению;
- сохранить воспроизводимый пайплайн обучения, инференса и экспорта модели.

## Что говорит статья

Статья Araújo et al., "Two-view fine-grained classification of plant species", Neurocomputing, 2022, предлагает двухэтапный подход:

1. `S-CNN (A)`: грубая классификация рода (`genus`) по глобальному виду листа, то есть по целому изображению. Цель этапа - получить ранжированный список кандидатов рода `Rk`.
2. `S-CNN (B)`: уточнение вида (`species`) внутри выбранных родов по локальному виду листа, то есть по центральному квадратному фрагменту. Цель этапа - различить близкие виды за счет жилкования и локальной текстуры.

Обе сети являются сиамскими: две одинаковые CNN-подсети с общими весами получают пару изображений, извлекают признаки, после чего считается расстояние между признаками. В статье используется L1-расстояние и обучение на положительных/отрицательных парах.

В статье проверялись AlexNet, GoogLeNet и VGG16. Лучший baseline в их экспериментах на PlantCLEF 2015 - VGG16: 75.09% против 73.30% у GoogLeNet и 71.98% у AlexNet. Финальная двухвидовая S-CNN на PlantCLEF 2015 дала top-1 0.87, top-3 0.94, top-5 1.0 при `Nr = 6` reference samples per class и `Rk = 30`.

Практическое решение для нашего проекта: брать за основу двухэтапную S-CNN из статьи, но реализовать backbone через современный PyTorch/timm или torchvision. С точки зрения защиты диплома самый близкий к статье вариант - VGG16, потому что он дал лучший результат в статье. Если вычислительные ограничения Colab будут мешать, можно добавить эксперимент с более легким backbone, но основной план нужно описывать через VGG16-like Siamese CNN.

## Данные

Базовый выбор: PlantCLEF 2015, потому что:

- он уже указан в РПЗ;
- статья использует PlantCLEF 2015;
- у датасета есть предопределенный test set;
- датасет несбалансирован и содержит мало изображений для части видов, что хорошо мотивирует S-CNN и few-shot/metric learning.

Важно проверить доступность полного скачивания PlantCLEF 2015. Если получение датасета окажется слишком долгим или закрытым, fallback для разработки приложения и отладки пайплайна - LeafSnap или другой открытый leaf dataset, но в тексте диплома основной эксперимент лучше держать на PlantCLEF 2015.

## Архитектура обучения

Планируемые модули:

- `src/data`: чтение метаданных, разметка `family/genus/species`, split, генерация пар;
- `src/preprocessing`: resize, нормализация, центральный crop для local view, аугментации;
- `src/models`: Siamese network wrapper, backbone, heads, distance layer;
- `src/train`: обучение `S-CNN (A)` для `genus` на global view и `S-CNN (B)` для `species` на local view;
- `src/inference`: построение reference index, расчет сходства, fusion и выдача top-k видов;
- `src/app`: PyQt-приложение;
- `notebooks`: Colab-ноутбук для обучения;
- `configs`: yaml-конфиги датасета, модели и обучения.

Предварительный алгоритм инференса:

1. Для входного изображения построить global view.
2. Сравнить его через `S-CNN (A)` с reference-изображениями родов.
3. Взять top `Rk` кандидатов рода и посчитать частоты родов как веса.
4. Для входного изображения построить local view центральным crop.
5. Через `S-CNN (B)` сравнить local view с reference-изображениями видов внутри выбранных родов.
6. Сформировать итоговый ранжированный список видов с учетом веса рода и similarity score.

## PyQt-приложение

Минимальные функции:

- выбор одного изображения;
- выбор нескольких изображений;
- выбор папки с изображениями;
- очередь/список выбранных файлов;
- запуск инференса по всем выбранным изображениям;
- сетка результатов: миниатюра, top-1, confidence/score, top-k;
- отдельный просмотр изображения: крупное изображение, top-k, genus/species, score, путь файла;
- отображение ошибок загрузки/инференса;
- настройка модели/reference index через конфиг или диалог выбора.

Первый рабочий прототип может использовать заглушку модели, чтобы быстро собрать UI и контракт инференса. Затем заглушка заменяется реальным `Predictor`.
